# Lamplight — Complete Personal AI Playground Brain Dump

I want to evolve Lamplight into a powerful, personal, local-first AI environment that combines an AI assistant, developer workbench, research desk, creative studio, knowledge management system, automation platform, and experimental playground for local models. I am building this primarily for myself, so I don't need to optimize it for monetization, subscriptions, user acquisition, or the average user's needs. I want the freedom to experiment with unusual ideas, build highly personalized workflows, and create features that I genuinely enjoy using. At the same time, I want the application to remain coherent instead of becoming a collection of disconnected features. I want to preserve everything that already works, including multiple bot personas, multiple model providers, custom system prompts, skills, memory, TTS, document support, live artifacts, the Model Lab, the Observatory, and the AI Arena with chess, debates, and multi-model experiments. My goal is to build on this foundation rather than rewrite the application unnecessarily.

## 1. Personal AI Workspace and Context Management

I want to introduce **Project Workspaces** where every major project has its own instructions, conversations, memory, documents, files, model preferences, skills, artifacts, and activity history. For example, I want a dedicated workspace for Lamplight development, another for software engineering projects, another for research and learning, and another for my fantasy-writing project. Each workspace should retain its own context so that I don't have to repeat the same information in every conversation. I want the ability to define project-specific instructions, attach relevant files, save important conversations, and switch between projects without mixing their memories or data. I also want a **Context Inspector** that shows exactly what is sent to a model, including system prompts, persona instructions, activated skills, conversation history, retrieved memories, document excerpts, tool results, and generation settings. It should estimate token usage, show context limits, identify conflicting or duplicate instructions, display omitted messages, and let me inspect or edit the context before sending a request. I want to pin important messages, exclude irrelevant conversation turns, remove individual memories from a request, regenerate summaries, and see how the final prompt was assembled. I also want a **Memory Control Center** that unifies personal memories, bot-specific memories, project knowledge, and conversation summaries. Every memory should have a source, scope, timestamp, and editing controls. I want to approve suggested memories, correct outdated information, merge duplicates, resolve contradictions, delete memories, and see why a particular memory was retrieved for a response. Temporary session context should remain separate from long-term memory. I want a **Global Quick Capture** feature that lets me rapidly save ideas, questions, notes, links, files, code snippets, and tasks without navigating through the application. I want to send captured items to Friend, Architect, Muse, a project workspace, or an inbox for later organization. Since Lamplight is a web application, I could support quick capture through a focused command palette, a PWA shortcut, or a browser extension, with an optional desktop companion for system-wide hotkeys. I also want **Conversation Branching and Replay**, allowing me to fork a conversation at any message, explore alternative directions, compare responses from different models, rerun old prompts with different models or settings, and inspect differences between response versions. Each replay should preserve the relevant prompt, model, skill, attachments, and generation settings. Finally, I want a customizable **Personal Launchpad** that displays pinned workspaces, favorite skills, available models, recent documents, unfinished experiments, saved artifacts, recent jobs, and a quick-capture field.

## 2. Model Intelligence, Context Engineering, and Experimentation

I want to make Lamplight better at selecting and managing local models instead of treating every model as interchangeable. I want a **Task-Based Model Router** that can recommend or select a model for coding, research, creative writing, vision, long-context tasks, quick questions, structured output, or tool use, while always allowing me to override the choice manually. I want a **Resource-Aware Scheduler** that considers available RAM and VRAM, active jobs, model loading costs, and concurrency before launching inference requests. It should queue work when necessary, avoid loading several large models simultaneously, unload models when appropriate, and let me configure resource and concurrency limits. I want detailed **Model Capability Profiles** describing supported context sizes, vision, tool calling, structured output, streaming, and reasoning controls. I want an **Adaptive Context Manager** that summarizes older conversation sections, preserves important facts, prioritizes recent relevant information, and warns before truncating context. I want a **Structured Output Mode** that accepts a JSON schema, requests structured responses, validates the returned output, displays validation errors, and optionally asks the model to correct malformed responses. I want an **Answer Verification Mode** in which a second model reviews an answer for unsupported claims, logical errors, missing edge cases, and contradictions, while keeping its critique separate from the original response. I want reusable **Generation Presets** for coding, research, quick answers, storytelling, and other workflows, with model-specific defaults and parameters. I also want configurable **Model Fallback** behavior so that a failed or unavailable model can be replaced by an alternative when appropriate. I want a **Request Recorder** that stores sanitized request metadata and responses for reproducibility, and I want the existing Model Lab to track changes across model versions, quantizations, prompts, context sizes, and generation settings. I want a **Prompt Debugger** that can answer questions about the actual requests Lamplight sends to models, including why a model ignored an instruction, whether a PDF actually entered the context, which memories were included, whether instructions conflicted, why a tool was called, and which parameters changed between two requests. It should inspect real request records rather than inventing explanations after a response has already been generated.

## 3. Developer Workbench and Local Repository Intelligence

I want to connect Architect to selected local Git repositories so it can inspect files, search symbols, understand repository structure, read documentation, analyze Git status and diffs, trace execution paths, and identify dependencies. I want it to help me understand unfamiliar codebases, investigate bugs across several files, find duplicated logic, locate missing tests, and suggest focused patches. Repository access should begin in read-only mode, with all proposed modifications displayed as reviewable diffs before I approve them. I want a **Safe Tool and Terminal Workbench** that supports controlled Python execution, file search, Git operations, test execution, and eventually shell commands. These capabilities should have separate permissions for read-only access, workspace file edits, test execution, and higher-risk operations. I want execution history that records the requested action, command or operation, exit code, output, and elapsed time. All code execution should happen in an appropriately isolated process or sandbox with timeouts, output limits, working-directory restrictions, and resource controls. I want a **Project Architecture Map** that visualizes modules, imports, APIs, database tables, configuration, tests, and dependencies. I should be able to select a module and inspect its responsibility, related files, callers, and relevant tests. I also want to compare architecture maps between commits to detect structural changes. The maps should be based on static analysis and repository evidence, with AI used to explain the resulting structure rather than invent it. I want a **Patch Lab** where two models can propose different solutions to the same engineering problem. Lamplight should display their diffs separately, run equivalent tests against isolated working trees, compare test results, and summarize quality and risk. It should preserve the original repository state, support rollback, and never commit or push changes automatically by default. Additional developer tools could include API request replay, log analysis, SQL explanation, database schema visualization, dependency auditing, endpoint testing, bug reproduction-case generation, and automated release checks. I want Architect to become a practical engineering assistant that can move from understanding a problem to proposing a change and verifying it, while preserving human control and keeping every important action inspectable.

## 4. Local Knowledge Library, Reading Desk, and Research Studio

I want a **Watch-Folder Knowledge Library** that indexes folders I explicitly select. Lamplight should detect added, changed, and deleted files; extract their contents; update its search index; and let me search across PDFs, Markdown, TXT, DOCX, HTML, EPUB, CSV, and JSON files where supported. I want full-text search, metadata filters, tags, and eventually local embeddings and hybrid retrieval when semantic search provides a clear benefit. Answers based on retrieved material should link to actual source passages, filenames, pages, or sections whenever possible. I want a **Research Notebook** where I can save highlighted passages, annotations, source links, claims, questions, and personal notes within project-specific collections. I should be able to ask questions across saved sources and create research summaries that distinguish direct quotations, sourced claims, my own notes, and model-generated inferences. I also want import and export support for ordinary Markdown folders so my knowledge is not trapped in a proprietary format. I want a dedicated **Reading Desk** for EPUBs, PDFs, and supported documents, with adjustable typography, dark mode, bookmarks, annotations, highlights, and reading progress. Selecting a passage should let me ask a question, request an explanation, create a note, or add the passage to my knowledge library. I want an AI reading companion that prioritizes the current book and clearly indicates when it uses information from elsewhere. I also want a **Personal Learning Studio** that converts selected documents, conversations, and notes into flashcards, interactive quizzes, concept maps, and revision sessions. It should track concepts I struggle with, schedule spaced repetition, gradually adjust difficulty, and offer alternative explanations when I answer incorrectly. Other useful document capabilities would include OCR for scanned PDFs, deduplication, document version comparison, section-by-section summaries, entity extraction, CSV visualization, and source-quality indicators. I particularly want an evidence-oriented mode in which claims derived from documents are traceable to supporting passages and unsupported conclusions are explicitly labeled as inference.

## 5. Creative Studio, Worldbuilding, and Persistent Artifacts

I want a **Story Studio** that develops Muse into a dedicated writing environment. It should organize characters, places, factions, timelines, events, relationships, world rules, scene drafts, and plot outlines as structured records. I want a scene board, character-arc tracker, plot timeline, continuity checker, and draft version comparison. The system should distinguish established canon, unfinished drafts, hypotheses, and discarded ideas. Muse should flag possible contradictions in character actions, locations, historical events, and world rules, while showing the source of the conflict so deliberate ambiguity is not mistaken for a mistake. I also want an **Interactive Worldbuilder** for fictional maps, regions, settlements, distances, trade routes, political borders, and historical events. Characters, factions, histories, and conflicts should be linked to locations. A timeline slider could show how borders, migrations, alliances, and wars change across different eras. I want to experiment with how geography, resources, trade, culture, and political incentives shape fictional civilizations. I also want a **Personal Mini-App Workshop** that transforms useful artifacts into persistent applications rather than one-off previews. I want to create tools such as a writing word counter, lore browser, study timer, prompt builder, data dashboard, project calculator, and other small utilities. Each saved tool should have its own files, settings, data, version history, and export capability, and I should be able to launch it directly from my personal dashboard. Generated applications must remain isolated from the main application and must not automatically gain access to my credentials or unrestricted filesystem.

## 6. Multimodal Local AI

I want to expand Lamplight beyond text while keeping everything local whenever the required models and hardware are available. I want a **Vision Workspace** that compares image-capable models, interprets screenshots, reads diagrams, extracts image text, and answers questions about visual material. I want **Screenshot Debugging**, where I can attach a screenshot of an error or interface, associate it with relevant source files and logs, and ask Architect to investigate. I want an **Audio Transcription Desk** that converts audio recordings into searchable transcripts with timestamps and summaries using local speech-to-text models. I also want to convert lectures and meetings into structured notes, topics, questions, and action items. Speaker identification should be optional and uncertainty should be made clear. An **Audio Library** could organize recordings and their transcripts with searchable metadata. I want a more complete **Voice Conversation Mode** that combines speech input, model responses, interruptible TTS, and conversational turn management. I also want optional local image generation through a backend such as ComfyUI, allowing me to generate images, save them to projects, and compare outputs. Eventually, I want a **Media Analysis Pipeline** that processes supported video files into transcripts, selected keyframes, timestamps, and searchable summaries. Lamplight should detect which capabilities a configured model actually supports and route each request accordingly instead of sending unsupported inputs to a model that cannot process them.

## 7. Workflow Recipes and Automation

I want a **Workflow Recipes** system that combines skills, tool calls, model requests, document processing, validation, and saved outputs into reusable workflows. I want to create a research workflow that gathers available sources, extracts claims, compares model analyses, and produces a sourced report. I want a development workflow that inspects a Git diff, generates tests, runs them in an isolated environment, and summarizes failures. I want a writing workflow that loads the story bible, drafts a scene, checks continuity, and performs a line edit. I also want a **Background Job Queue** for long-running work such as indexing documents, transcribing audio, evaluating models, creating artifacts, and processing batches. Jobs should show progress, current model, resource usage where available, cancellation controls, retry behavior, and saved results. They should survive page reloads, recover sensibly after restarts, and report failures without hanging. I want a **Scheduled Local Tasks** system for recurring document indexing, project summaries, saved prompt evaluations, backup reminders, and learning reviews. It should use real persisted schedules, execution history, and clear pause and disable controls. I also want a **Tool and Connector Registry** for local files, Git repositories, notes vaults, explicitly configured HTTP services, and compatible tool servers such as MCP. Every tool should declare its operations and permissions, and I should be able to inspect or disable it. Sensitive actions must require appropriate approval, and tools should not be automatically available to every bot.

## 8. AI Arena, Simulations, and Experimental Playgrounds

I want to expand the existing Arena with a persistent **Arena League** featuring chess tournaments, debate competitions, logic puzzles, coding challenges, creative writing duels, and collaborative problem-solving. It should support tournament brackets, adjustable conditions, replay, model-specific statistics, and challenge-specific ratings rather than treating one score as a universal measure of intelligence. I also want an **AI Game Master** that runs persistent text-based role-playing adventures with quests, maps, inventory, NPCs, factions, locations, and consequences. The underlying game state should be stored separately from narrative text, and different models could act as narrator, NPC, quest designer, or rules referee. I want a **Civilization Sandbox** where fictional factions manage resources, populations, territory, trade routes, policies, alliances, and competing objectives. Different models could propose actions while a deterministic simulation engine calculates actual outcomes. I could run experiments involving shortages, trade wars, diplomacy, migrations, territorial conflicts, and competing settlement strategies, then compare how different models respond to the same conditions. I also want an **AI Mystery and Puzzle Room** where one model creates a mystery with a fixed solution and another plays detective. Suspects, clues, evidence, and deductions should be stored as structured state so the mystery remains coherent rather than changing its answer whenever the model generates new text. Other variations could include escape rooms, logic puzzles, and interactive detective cases. Finally, I want an **AI Radio** mode that lets two selected personas produce short discussions, debates, book conversations, fictional broadcasts, or entertaining dialogues. I should be able to select the topic, duration, and voices, edit the script, regenerate individual turns, and convert the result to audio using the existing TTS system. Conversations should remain bounded so the models do not talk indefinitely.

## 9. Deep Personalization and Interface Design

I want a **Persona Designer** for creating and versioning custom bots with individual system prompts, voices, models, memories, skills, generation settings, and permissions. I want temporary personas for experiments without having to permanently add every configuration as a bot. I also want **Personal Response Preferences** that control default answer length, formatting, directness, criticism, uncertainty handling, and whether the model asks clarifying questions. Individual bots and project workspaces should be able to override these preferences. I want **Response Collections** where I can save useful explanations, code snippets, research findings, prompts, and creative passages to searchable collections with tags, notes, source links, and references to their original conversations. A **Personal Data Timeline** should show what information Lamplight stored, when it was updated, which conversation produced it, and which bot or workspace can access it. I want a **Custom Theme Studio** for editing colors, typography, spacing, background effects, code fonts, and panel layouts, with import and export for theme configurations. I also want **Interface Profiles** that save different arrangements for coding, reading, research, writing, and Arena sessions. These should change the layout according to my workflow without duplicating the underlying features or data.

## 10. Privacy, Data Portability, and Reliability

I want automatic **Backup Snapshots** of the database and selected files, with retention limits and tested restoration. I want **Selective Export** so I can export a bot, workspace, conversation collection, prompts, artifacts, or memory independently. I want **Data Portability** through readable formats such as Markdown, JSON, and original files wherever practical. I want a **Privacy Inspector** showing which files, network endpoints, and tools a workflow can access. I want clear **Network Controls** for local-only operation, explicitly approved network access, and permitted external lookup tools. I want **Safe Deletion** that accounts for conversations, attachments, memory entries, indexed document chunks, cached outputs, and related metadata according to an explicit deletion policy. I also want **Crash Recovery** that preserves completed partial results, recovers interrupted jobs where possible, and avoids duplicate execution after a restart. A **Maintenance Dashboard** should display database size, search-index size, TTS cache, temporary artifacts, backups, failed background jobs, and other storage that might need cleanup. I want to test backup restoration regularly rather than merely assuming backups work. I also want appropriate authentication checks, secure password hashing, origin and CSRF protections as relevant to the deployment, upload validation, careful handling of API credentials, and safe network-binding defaults. The application's local-first design should not be treated as a substitute for security.

## 11. Advanced Model Research and Multi-Model Workflows

I want a **Multi-Model Collaborative Project** system where one model creates a proposal, another implements it, a critic reviews the output, and a verifier runs objective tests. Each step should have a defined input and output contract, budget, and termination condition. I should be able to inspect the results and approve or reject any handoff. I also want an optional **Knowledge Graph** that links projects, concepts, documents, facts, events, characters, and other entities. Every relationship should have an inspectable source, and I should be able to correct inaccurate relationships. I want to begin with explicit entities and links before adding complex graph retrieval. I want **Model Behavior Experiments** that maintain a corpus of prompts I care about and run them against different model versions, quantizations, system prompts, context sizes, and generation parameters. Lamplight should detect regressions and compare quality, speed, resource usage, and consistency. I also want **Long-Running Autonomous Tasks** that can process a batch of PDFs, evaluate multiple models, or analyze a repository under explicit budgets, deadlines, resource limits, and checkpoints. These tasks should provide pause, cancel, and review controls rather than operating indefinitely. Finally, I want a **Full Execution Trace** that lets me inspect the events behind an answer, including prompt assembly, retrieved memory, model requests, tool calls, tool results, validation, retries, and the final response. Sensitive values should be redacted, and detailed prompt logging should be configurable.

## 12. External and Local Integrations

I want an optional **Notes-Vault Integration** for a local Markdown directory or compatible knowledge vault, allowing Lamplight to search existing notes and save linked research or conversation summaries as ordinary files without overwriting external edits. I want a **GitHub Integration** for authorized access to repositories, issues, pull requests, and documentation, with read-only behavior by default and approval before remote modifications. I want **Local Service Integration** for explicitly configured services such as Ollama, image-generation systems, and compatible inference servers, including connection checks and health monitoring. I also want a **Browser Companion** that can send user-selected text or a page to Lamplight, save a source to the research library, or open a conversation with selected content attached. It should only access page content through explicit user-triggered actions. A **Mobile Companion Interface** should make quick capture, voice interaction, document lookup, saved conversations, and job status comfortable on a phone. Remote access should remain opt-in and secured rather than exposing the service openly to the internet.

## 13. Overall Vision and Implementation Approach

I want Lamplight to have three interconnected layers. The first is a **personal knowledge and context layer** that manages projects, conversations, documents, preferences, memories, and source-backed information. The second is a **capability layer** that connects different models to tools, jobs, integrations, permissions, and reusable workflows. The third is a **playground layer** where I can experiment with model comparisons, debates, chess, writing environments, image generation, role-playing adventures, civilization simulations, and other creative projects. I want language models to handle interpretation, reasoning, and generation, while deterministic software handles permissions, persistent state, validation, simulation rules, execution limits, and measurement. I want to begin by improving existing systems that unlock multiple capabilities, particularly Project Workspaces, Context Inspector, Memory Control Center, execution tracing, and backup and restore. Then I want to connect Lamplight to real work through repository inspection and controlled tool execution, build reusable workflows and a background job queue, and develop the knowledge and reading environment. Once the foundation is reliable, I want to pursue the more experimental features according to what I enjoy using most. I don't want to implement every idea simply because it exists in this document. I want this to be a living brain dump that gives me a broad vision for Lamplight while allowing me to choose features incrementally. My ultimate goal is to build a highly personalized AI environment that helps me write software, research topics, learn new things, manage projects, create fictional worlds, experiment with local models, and explore unusual ideas—all while keeping control over my data, my tools, and how the system behaves.
